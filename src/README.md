# КТ2. Контроль полноты заполнения блистера
Тема практики: «Внедрение систем контроля качества на основе компьютерного зрения»
Задача: проверка наличия таблеток в ячейках одного типа блистера до запайки по фотографии сверху

## Среда и зависимости
- Python 3.12 (процедурная реализация, без собственных классов)
- OpenCV (opencv-python, указан в `requirements.txt`)
- VS Code и терминал. База данных не требуется: данные записываются в JSON

## Установка и запуск
Открыть терминал в корневой папке репозитория:

```bash
python3 --version
python3 -m pip install -r src/requirements.txt
python3 src/main.py
```

На запрос `Введите путь к изображению` вставить путь или нажать enter:
При фотографиях других размеров, поворота или расположения ячеек необходимо отдельно настроить `src/template.json`

## Пример работы

В тестовой фотографии 18 ячеек, из них 7 и 10 пустые

```text
Попытка 1 из 3
Введите путь к изображению: src/images/blister.png
Изображение пригодно для проверки
Количество ячеек: 18
...
Ячейка 7 - empty
...
Ячейка 10 - empty
...
Пустые ячейки: [7, 10]
Неопределённые ячейки: []
Введите имя оператора: natsya
Предварительное заключение: Обнаружена пустая ячейка
Подтвердить результат? (да/нет): да
Требуется разбор специалистом? (да/нет): нет
Итоговое заключение: Обнаружена пустая ячейка
```

После завершения появляется `src/inspection.json` с результатами, а копия последней доступной фотографии при необходимости сохраняется в `src/images/inspection_image.png`

Программа перезаписывает `inspection.json` при каждом запуске и демонстрирует **одну проверку**. История нескольких блистеров пока не реализована

## Сопоставление операций BPMN и функций
| Операция на BPMN | Функция |
| --- | --- |
| Получить изображение блистера | `load_image()` и `get_image_with_retries()` |
| Проверить пригодность изображения | `check_image_quality()` |
| Повторно получить изображение | `get_image_with_retries()` (не более 3 попыток) |
| Применить схему расположения ячеек | `load_template()`, `apply_cell_template()` |
| Оценить заполненность ячеек | `analyze_cells()` |
| Сформировать предварительное заключение | `make_preliminary_decision()` |
| Подтвердить или исправить результат | `confirm_result()` |
| Проверить блистер вручную | `manual_inspection()` |
| Рассмотреть спорный случай | `specialist_review()` |
| Сохранить изображение и результат проверки | `save_inspection()` |

## Алгоритмы и сложность
- `analyze_cells`: для каждой из `n` ячеек просматривает до `p` пикселей. Время O(nхp), дополнительная память O(n+p) без учёта входной фотографии
- `make_preliminary_decision`: один проход по `n` результатам. Время O(n), дополнительная память O(n)

## Структура JSON
`src/template.json` содержит шаблон блистера и 18 записей ячеек
`src/inspection.json` содержит восемь списков, соответствующих ER-модели:
`series`, `blisters`, `templates`, `template_cells`, `images`, `operators`, `inspections`, `cell_results`
Между проверками и ячейками шаблона связь M:N реализована через `cell_results` с составным ключом `(inspection_id, cell_id)`

## Дополнительные сценарии
- Если изображение не открывается или не проходит проверку качества, программа попросит другое. После 3 попыток предложит ручную проверку оператором
- Оператор может подтвердить или изменить предварительное заключение
- По запросу оператора результат может рассмотреть специалист
- При отсутствии доступного файла изображение в JSON регистрируется с `file_path: null`, а список `cell_results` пуст
